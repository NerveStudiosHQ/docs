---
title: "Global blips and access"
description: "Give admins access with ACE permissions, add server-wide blips every player sees, and choose which staff groups may."
---

Global blips are visible to every player on the server, for things like the city hall, hospitals, jobs or event areas. Only staff with global access can add, edit or delete them. Players can still hide a global blip from their own map.

Who can do what is set with ACE permissions, in `server.cfg` or from the **Access** tab in the menu.

## Permissions

| ACE | Gives |
| --- | --- |
| `blipcreator` | Full access: personal blips, global blips and the **Access** tab |
| `blipcreator.global` | Create, edit and delete global blips |
| `blipcreator.use` | Create and share personal blips. Only needed when `Access.PersonalForEveryone = false` |

The names follow `Access.Ace` in `shared/config.lua`. With `Ace = 'mapblips'` they become `mapblips`, `mapblips.global` and `mapblips.use`. Change it if `blipcreator` clashes with another resource.

| | Private, shared and group blips | Global blips | Access tab |
| --- | --- | --- | --- |
| Every player (default) | Yes | Sees them | No |
| `blipcreator.global` | Yes | Add, edit, delete | No |
| `blipcreator` (full access) | Yes | Add, edit, delete | Yes |

## Give access in server.cfg

Full access for your admins:

```cfg
add_ace group.admin blipcreator allow
```

Global blips for moderators, and personal blips for VIPs when `PersonalForEveryone` is `false`:

```cfg
add_ace group.mod blipcreator.global allow
add_ace group.vip blipcreator.use allow
```

ESX and QBox put their staff in groups like `group.admin` when they join. On a standalone server, add players to a group yourself:

```cfg
add_principal identifier.license:YOUR_LICENSE group.admin
```

## Give access from the menu

Admins with full access can grant the same permissions to ACE groups without touching `server.cfg`:

1. Open the menu and click **Access** in the side bar.
2. Type the group name, for example `mod` for `group.mod`.
3. Turn on **Global** to let them place global blips, and **Personal** to let them make their own blips.
4. Click **Add group**.

Changes are saved and apply straight away, with no restart. Turn a toggle off or remove the group to take access away again. `Access.MaxGroups` caps how many groups the tab can hold (25 by default).

<Callout type="warn">

The **Access** tab needs these two lines in `server.cfg`. Without them, the groups are saved but their members get no access, and the server console warns you on start.

```cfg
add_ace resource.nerve_blipcreator command.add_ace allow
add_ace resource.nerve_blipcreator command.remove_ace allow
```

</Callout>

Permissions you wrote in `server.cfg` yourself are never removed by the **Access** tab. The **Personal** toggle only matters when `Access.PersonalForEveryone = false`.

## Personal blips for staff only

By default every player can make, share and group their own blips. To limit that to staff, set this in `shared/config.lua`:

```lua
Access = {
    PersonalForEveryone = false,
},
```

Then only players with `blipcreator`, `blipcreator.use`, or a group with **Personal** turned on in the **Access** tab can open the menu to make their own blips. Everyone still sees global blips.

## Add a global blip

1. Click **Global blips** in the side bar, then **New global blip**.
2. Fill in the editor the same way as a normal blip (see [Using the menu](/nerve_blipcreator/using-the-menu#create-a-blip)).
3. Click **Create blip**. Every player sees it straight away.

Staff with global access can also turn on **Global blip** in the editor when creating from **My blips**, or turn on **Create as global** when duplicating any blip.

## Global-only icons

You can reserve icons for global blips so players can't use them on their own blips, such as police or hospital icons. In `shared/config.lua`:

```lua
Sprites = {
    GlobalOnly = { 60, 61, 137 },
},
```

Find icon IDs in the icon picker by searching or hovering an icon.

## Limits

`Limits.GlobalBlips` caps how many global blips the server can have (500 by default). Lowering it never hides global blips that already exist; it only stops new ones.
