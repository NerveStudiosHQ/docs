## The resource doesn't start

The server console names a missing requirement:

```
Could not find dependency ox_lib for resource nerve_blipcreator.
Could not find dependency oxmysql for resource nerve_blipcreator.
Could not find dependency /onesync for resource nerve_blipcreator.
```

- For `ox_lib` or `oxmysql`, install that resource and `ensure` it **before** `nerve_blipcreator` in `server.cfg`. See [Installation](/nerve_blipcreator/installation#step-2-add-it-to-server-cfg).
- For `/onesync`, turn OneSync on in txAdmin or with `set onesync on` in `server.cfg`.

## The menu doesn't open

- **"Your blips are still loading, try again in a moment."** Wait a few seconds after joining. If it never goes away, check the server console for database errors and that oxmysql starts before this script.
- **"You do not have access to the blip creator."** `Access.PersonalForEveryone` is `false` and you don't have `blipcreator`, `blipcreator.use` or a group with **Personal** access. See [Global blips and access](/nerve_blipcreator/global-blips-and-access).
- **Nothing happens at all.** Check that the folder is named exactly `nerve_blipcreator` and that the resource started without errors.
- **The menu is missing or blank.** Re-download the script from your Cfx.re Portal. A file was lost when it was unzipped or uploaded.

## I'm an admin but I can't add global blips

1. Check `server.cfg` has `add_ace group.admin blipcreator allow`, or that your group has **Global** turned on in the **Access** tab.
2. Check you are in that group. In the server console, run `test_ace player.<your server id> blipcreator`. It should say `true`.
3. After changing `server.cfg`, restart the server or run the `add_ace` line in the console, then reopen the menu.

## Groups added in the Access tab don't get access

The server console shows this on start:

```
groups are configured but the resource cannot run add_ace. Add these to server.cfg:
  add_ace resource.nerve_blipcreator command.add_ace allow
  add_ace resource.nerve_blipcreator command.remove_ace allow
```

Add both lines to `server.cfg` and restart the server.

## Nobody shows under "Players near you"

- The other player must be within `Sharing.NearbyDistance` metres (15 by default). Stand closer and click **Refresh**.
- `Sharing.Enabled` and `Sharing.Nearby` must be `true`.
- When `Access.PersonalForEveryone` is `false`, only players with access to the menu can be invited.

## "Your account has no identifier, so you cannot share blips."

The player has no identifier of the type set in `Security.Identifier` (`license` by default), and the console shows `<id> has no usable identifier; only global blips are shown to them`. This happens with some modified clients. Keep `Identifier = 'license'` unless you have a reason to change it. Private blips still work for that player.

<Callout type="warn">

Changing `Security.Identifier` on a live server hides every shared and group blip players already have, because they were saved under the old identifier.

</Callout>

## A share code doesn't work

- Codes are 8 letters and numbers, for example `K7P2-QX9M`. Dashes, spaces and case don't matter.
- The owner may have made a new code or turned the code off. Ask them for the current one.
- After too many wrong codes, a player is locked out of codes for a while. Wait and try again.

## "Slow down a little."

The player sent requests faster than the rate limit allows. Normal use never hits it. If players on your server do, raise `Security.RateScale`, for example to `2.0`.

## A blip shows blank or as the wrong icon

Your server's game build is older than the icon. Either set a newer build with `sv_enforceGameBuild` in `server.cfg`, or lower `Sprites.Max` so players can't pick it.

## Icon previews in the menu are empty

The icon picker loads its previews from the internet, set by `Sprites.ImageUrl`. If your players can't reach that site, point it at your own https host, or set it to `''` to hide the previews. The blips on the map aren't affected.

## My private blips are gone

Private blips are saved on the player's own PC for your server. They are lost if:

- the player reinstalls FiveM or clears its local data
- they play from a different PC

To keep a blip across PCs, share it or add it to a group. Shared and group blips are saved on the server.

## Notifications don't show or look wrong

Notifications use ox_lib by default. To use your server's system, edit `Editable.Notify` in `shared/editable.lua`. See [Notifications](/nerve_blipcreator/notifications-and-languages#notifications). If your code errors, the message falls back to the GTA feed.

## The menu is in the wrong language

Set ox_lib's language in `server.cfg` with `setr ox:locale <code>`, for example `setr ox:locale de`, and restart the server.

## Yellow warnings in the console on start

A value in `shared/config.lua` has the wrong type or is out of range, for example:

```
Config.Ui.Accent must be a hex colour like "#a855f7"; using the default
```

The warning names the option. The script uses that option's default until you fix it.

## "could not create tables"

```
could not create tables, import sql/nerve_blipcreator.sql manually: ...
```

Your database user can't create tables. Import `sql/nerve_blipcreator.sql` with your database tool, then set `Database.AutoInstall = false` in `shared/config.lua`.

## The cursor is stuck on screen

Press **Esc** to close the menu. The cursor is also released when the resource stops or restarts.

## Still stuck?

Set `Debug = true` in `shared/config.lua`, restart the resource and reproduce the problem. Then open a ticket on [Discord](https://discord.gg/nervestudios) with your server console and F8 output. See [Support](/general/support) for what to include.
