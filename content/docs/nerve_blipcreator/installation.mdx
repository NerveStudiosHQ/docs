---
title: "Installation"
description: "Install Nerve Studios Blip Creator, set up the admin permission and open the menu for the first time."
---

## Requirements

- A recent FiveM server artifact
- [oxmysql](https://github.com/overextended/oxmysql), started before this resource
- OneSync, if you want players to invite people near them (on by default on current servers)

No framework is needed. The script works on ESX, Qbox or a server with no framework at all.

## Step 1 — Add the resource [#step-1-add-the-resource]

1. Download the script from your purchase and unzip it.
2. Make sure the folder is named exactly `nerve_blipcreator`.
3. Put it in your `resources` folder, for example `resources/[nerve]/nerve_blipcreator`.

<Callout type="warn">

Don't rename the folder. Exports, the database tables and the menu all use the name `nerve_blipcreator`.

</Callout>

## Step 2 — Add it to server.cfg [#step-2-add-it-to-server-cfg]

Add these lines to `server.cfg` **after** `ensure oxmysql`:

```cfg
add_ace group.admin blipcreator allow
add_principal identifier.license:YOUR_LICENSE group.admin

add_ace resource.nerve_blipcreator command.add_ace allow
add_ace resource.nerve_blipcreator command.remove_ace allow

ensure nerve_blipcreator
```

What each line does:

- `add_ace group.admin blipcreator allow` makes everyone in `group.admin` a **manager**. Managers can do everything, including the **Access** tab.
- `add_principal identifier.license:... group.admin` puts you in that group. Replace `YOUR_LICENSE` with your license identifier. You can find it in txAdmin under the player's identifiers. Skip this line if your framework already puts you in `group.admin`.
- The two `resource.nerve_blipcreator` lines let the script give access to the staff groups you add in the **Access** tab. Without them, groups you add there get no access.

<Callout type="info">

ESX and Qbox already add admins to `group.admin` when they join, so most servers only need the first line and the two `resource.` lines.

</Callout>

## Step 3 — Database [#step-3-database]

You don't need to do anything. The tables are created automatically the first time the resource starts.

If your database user can't create tables, import `install/nerve_blipcreator.sql` yourself. Then set `Config.Database.AutoInstall = false` in `config.lua`.

## Step 4 — Configure [#step-4-configure]

Open `config.lua` in the resource folder. Every option is explained right there. The defaults work for most servers, but these are worth checking:

- `Config.Locale` sets the language.
- `Config.Command` and `Config.Keybind` set how players open the menu.
- `Config.Notify` sets which notification system to use.
- `Config.Access.PersonalForEveryone` decides whether every player can make their own blips or only staff.

See [Configuration](/nerve_blipcreator/configuration) for every option.

## Step 5 — Start and test [#step-5-start-and-test]

1. Restart your server, or run `refresh` then `ensure nerve_blipcreator` in the console.
2. Check the console for a line like `loaded 0 global blips and 0 access groups`.
3. Join the server and type `/blips`.
4. Click **New blip**, give it a name and click **Create blip**. It appears on your map straight away.

<Callout type="info">

If the console shows a yellow warning about `config.lua`, a value was typed wrong. The script uses a safe default for that option and tells you which one to fix.

</Callout>

## Updating

1. Back up `config.lua`, `notify.lua` and any locale files you changed.
2. Replace the resource folder with the new version.
3. Copy your changes back.
4. Restart the resource.

Your blips are kept. Private blips are stored on each player's PC, and shared and global blips are in your database.
