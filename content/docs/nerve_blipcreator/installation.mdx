title: "Installation"
description: "Install Nerve Studios Blip Creator, give your admins access and open the menu for the first time."
---

## Requirements

- [ox_lib](https://github.com/overextended/ox_lib/releases)
- [oxmysql](https://github.com/overextended/oxmysql/releases)
- OneSync (on by default on current servers)

No framework is needed. The script works on ESX, QBox or a server with no framework at all.

## Step 1: add the resource [#step-1-add-the-resource]

1. Download `nerve_blipcreator` from your [Cfx.re Portal](https://portal.cfx.re/assets/granted-assets).
2. Make sure the folder is named exactly `nerve_blipcreator`.
3. Put it in your `resources` folder, for example `resources/[nerve]/nerve_blipcreator`.

<Callout type="warn">

Don't rename the folder. Other scripts reach the exports by the name `nerve_blipcreator`.

</Callout>

## Step 2: add it to server.cfg [#step-2-add-it-to-server-cfg]

Add these lines to `server.cfg`, **after** oxmysql and ox_lib:

```cfg
ensure oxmysql
ensure ox_lib
ensure nerve_blipcreator

add_ace group.admin blipcreator allow

add_ace resource.nerve_blipcreator command.add_ace allow
add_ace resource.nerve_blipcreator command.remove_ace allow
```

What each line does:

- The `ensure` lines start the requirements first, then the script.
- `add_ace group.admin blipcreator allow` gives everyone in `group.admin` full access: personal blips, global blips and the **Access** tab. ESX and QBox put their admins in `group.admin`. On a standalone server, add yourself with `add_principal identifier.license:YOUR_LICENSE group.admin`.
- The two `resource.nerve_blipcreator` lines let the script grant access to the staff groups you add in the **Access** tab. You only need them if you use that tab.

See [Global blips and access](/nerve_blipcreator/global-blips-and-access) for every permission.

## Step 3: database [#step-3-database]

Nothing to do. The tables are created on the first start and updated on later starts.

If your database user can't create tables, import `sql/nerve_blipcreator.sql` yourself, then set `Database.AutoInstall = false` in `shared/config.lua`.

## Step 4: language [#step-4-language]

The script uses ox_lib's language. English is the default. For another language, add this to `server.cfg`:

```cfg
setr ox:locale de
```

Included: `en`, `de`, `es`, `fr`, `it`, `nl`, `pl`, `pt` and `tr`. See [Notifications and languages](/nerve_blipcreator/notifications-and-languages).

## Step 5: start and test [#step-5-start-and-test]

1. Restart your server.
2. Join and type `/blips`.
3. Click **New blip**, give it a name and click **Create blip**. It appears on your map straight away.

<Callout type="info">

The console stays silent on a good start. A yellow warning means a value in `shared/config.lua` was typed wrong; the script uses that option's default and names it so you can fix it.

</Callout>

Then look through [Configuration](/nerve_blipcreator/configuration) for the options worth changing, such as the command, a default key and the menu colour.

## Updating

1. Back up `shared/config.lua`, `shared/editable.lua` and any locale files you changed.
2. Replace the resource folder with the new version from your Cfx.re Portal.
3. Copy your changes back.
4. Restart the server.

Your blips are kept. Private blips are stored on each player's PC, and shared, group and global blips are in your database.

## Upgrading from 1.0.0 [#upgrading-from-1-0-0]

Version 1.0.1 moves the settings and adds two requirements. Do these steps once when you update from 1.0.0:

1. Copy your values from the old `config.lua` into the new `shared/config.lua`, then delete the old `config.lua`. The option names are the same, except `Config.Locale` and `Config.Notify`, which are gone.
2. The language now comes from ox_lib. Set it in your `server.cfg` with `setr ox:locale de` (or your language code).
3. Notifications are now set in `shared/editable.lua`. They use ox_lib by default, and the file has ready examples for the common notification resources. See [Notifications](/nerve_blipcreator/notifications-and-languages#notifications).
4. ox_lib and OneSync are now required. Start ox_lib before this script in your `server.cfg`.
5. The `install/` folder is now called `sql/`. The tables are still created and updated on start, so there is nothing to run by hand.

Your existing blips, groups and access settings carry over.
